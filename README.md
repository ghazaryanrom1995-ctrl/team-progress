# Թիմի առաջընթացը՝ GitHub Copilot-ով

Այս նախագիծը ձեր արդեն տեսած վահանակի **ամբողջ կոդն** է։ Կա աշխատակիցների գրանցում, ամսական առաջադրանքների ու դիտարկումների հաշվարկ, գրաֆիկ, Excel ներմուծում/արտահանում և շարժական տեսք։ GitHub-ում կպահվի կոդը, GitHub Pages-ը կտա անկախ հղում, իսկ Copilot-ը կօգնի փոփոխել կոդը։

> **Տվյալների պահման սահմանափակում.** Այս տարբերակում վահանակի գրառումները և Excel-ից ներմուծած տվյալները պահվում են տվյալ բրաուզերում (`localStorage`)։ Հղումը ուրիշ սարքից բացելիս տվյալներն ինքնաբերաբար չեն փոխանցվում։ Ամեն փոփոխությունից հետո ներբեռնեք պահուստային Excel-ը։ Մի տեղադրեք թիմի անձնական տվյալները հրապարակային GitHub պահոցում։ Համատեղ տվյալների համար անհրաժեշտ կլինի առցանց տվյալների բազա և մուտքի վերահսկում։

## 1. Տեղադրել GitHub-ում՝ առանց հրամաններ գրելու

1. Ներբեռնեք այս նախագծի ZIP-ը և Windows-ում ընտրեք **Extract All**։ Բացեք ստացված `team-progress-github` պանակը։
2. Մուտք գործեք [GitHub](https://github.com/) և բացեք [New repository](https://github.com/new)։ Անվանեք այն `team-progress`, ընտրեք **Public**, սեղմեք **Create repository**։ Ազատ `github.io` հասցեի համար վճարովի դոմեն պետք չէ։
3. Նոր պահոցում ընտրեք **Add file → Upload files**։ Ստացված պանակի **ներսի ամբողջ պարունակությունը** քաշեք վերբեռնման պատուհան (ներառյալ `.github` պանակը)։ Մի վերբեռնեք ZIP-ը որպես մեկ ֆայլ։ Սեղմեք **Commit changes**։
4. Պահոցի **Settings → Pages** բաժնում **Build and deployment → Source** դաշտի համար ընտրեք **GitHub Actions**։
5. Բացեք **Actions** բաժինը։ Եթե `Publish team progress` գործողությունն արդեն ավարտվել է կանաչ նշանով, անցեք հաջորդ քայլին։ Եթե այն ձախողվել էր մինչև Pages-ը միացնելը, բացեք գործողությունը և ընտրեք **Re-run all jobs** (կամ **Run workflow**)։
6. **Settings → Pages** էջում կերևա ձեր իրական հասցեն՝ մոտավորապես `https://ՁԵՐ-ՕԳՏԱՆՈՒՆԸ.github.io/team-progress/`։ Բացեք այն մեկ այլ բրաուզերում ևս։

**Netlify-ից արդեն մուտքագրած տվյալները տեղափոխելու համար** հին կայքում նախ սեղմեք **Պահուստային Excel** և պահեք ֆայլը։ Ապա GitHub Pages-ի նոր կայքում սեղմեք **Excel ներմուծել** և ընտրեք այդ ֆայլը։ Միայն կոդը GitHub տեղափոխելով նախկին գրառումները չեն տեղափոխվում, քանի որ բրաուզերը դրանք պահում է ըստ կայքի հասցեի։

GitHub Free-ի դեպքում GitHub Pages-ի կոդի պահոցը պետք է լինի Public։ Կայքի հասցեն ինքնուրույն է և ChatGPT հաշիվ չի պահանջում։

## 2. Փոփոխել կայքը Copilot-ով

Ամենահասկանալի ճանապարհը **GitHub Desktop + Visual Studio Code** ծրագրերն են։ Մուտք գործեք նույն GitHub հաշվով, GitHub Desktop-ում ընտրեք **File → Clone repository**, ընտրեք ձեր `team-progress` պահոցը, ապա բացեք այդ պանակը VS Code-ում։ Copilot Chat-ում ընտրեք **Agent** և գրեք խնդրանքը հայերեն։ Copilot Free-ը սահմանափակ օգտագործմամբ է. GitHub.com-ի cloud agent-ի որոշ հնարավորություններ կարող են պահանջել վճարովի պլան։

Օրինակ՝ Copilot-ին ուղարկեք սա.

> Այս նախագծում պահպանելով ներկայիս հայերեն դիզայնը՝ ավելացրու աշխատակցի ցուցանիշների նոր բաժին։ Ստուգիր `npm run typecheck` և `npm run build`, ասա՝ ինչ փոխվեց։ Մի փոխիր տվյալների պահման եղանակը և մի հրապարակիր գաղտնի տվյալներ։

Հաստատելուց հետո GitHub Desktop-ում գրեք փոփոխության կարճ նկարագրություն, սեղմեք **Commit to main**, ապա **Push origin**։ GitHub Pages-ը նոր տարբերակը կհրապարակի ավտոմատ։ Պատրաստի կայքում ցուցանիշները փոխելու համար Copilot պետք չէ. օգտագործեք **Ավելացնել գրառում**, **Excel ներմուծել** և **Պահուստային Excel** կոճակները։

## 3. Եթե պետք է բոլորի համար նույն տվյալները

Copilot-ին խնդրեք նախագծել առանձին առցանց տվյալների բազա, ադմինի մուտք և Excel-ից մեկանգամյա ներմուծում։ Նախ հաստատեք՝ ով կարող է **փոխել** տվյալները և ով միայն **տեսնել**։ Կոդի պահոցը ինքնուրույն տվյալների բազա չէ, իսկ GitHub Pages-ը միայն կայքի ֆայլերն է հրապարակում։ Գաղտնի բանալի մի ավելացրեք բրաուզերի կոդի մեջ։

## Մշակողի հրամանները

Պահանջվում է Node.js 22։ Նախագծի պանակում՝

```bash
npm ci
npm run typecheck
npm run build
npm run dev
```

Վերջին հրամանը տեղում փորձելու համար է. արտադրական հրապարակումը կատարվում է GitHub Actions-ով։
